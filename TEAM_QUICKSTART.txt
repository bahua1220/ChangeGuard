ChangeGuard 组内试用说明
版本：0.4.0-mvp.20261128
Sprint 对比已合并到团队仓库；本版本新加的潜在遗漏修改检查目前在本地完成、待提交。

一、获取团队代码
团队仓库：https://github.com/bahua1220/ChangeGuard
运行 git clone https://github.com/bahua1220/ChangeGuard.git，再进入 ChangeGuard 文件夹。
也可以下载仓库 ZIP 后解压。工具分析的目标可以是其他人的公开 GitHub 项目。

二、准备环境
安装 Python 3.12 和 Git，并确保命令行能执行 python 和 git。
Windows：在项目文件夹中打开 PowerShell，依次执行：
    powershell -ExecutionPolicy Bypass -File .\setup.ps1
    powershell -ExecutionPolicy Bypass -File .\run.ps1
浏览器访问：http://localhost:8501
启动终端按 Ctrl+C 可停止服务。

macOS/Linux：在解压后的目录内依次执行：
    python3 -m venv .venv
    source .venv/bin/activate
    python -m pip install -r requirements.lock
    python -m streamlit run app.py

三、先体验演示数据
点击“载入演示仓库”，无需真实模型密钥。
完整演示数据应为：18 条提交、3 个作者标识、14 个文件路径、新增 62 行、删除 8 行。
依次查看概览、开发者活动、文件与提交、Sprint 报告、Sprint 对比，并下载 Markdown 报告。
演示仓库会自动创建 Sprint 1（11 月 9–14 日）和 Sprint 2（11 月 15–22 日），各 9 条提交。
在“Sprint 工作区”选择 Sprint，图表与报告会同步切换。
展开“创建或编辑 Sprint”，可以创建、修改、删除并持久保存迭代定义。
在提交的文件详情中，Changed methods 显示变更前/后的方法签名和行号。
报告导出会包含 Sprint 名称、日期及方法位置列表。
进入“Sprint 对比”，选择 A = Sprint 1、B = Sprint 2。
两期均为 9 条提交；A 新增/删除 38/1 行，B 为 24/7 行；时长为 6/8 天。
可交换两期、查看模块和文件对比，并下载独立的 Markdown 对比报告，无需 AI。

另一个演示入口：“载入遗漏检测演示”。它生成独立的 15 条合成提交，不改变原有演示。
进入“遗漏修改检查”，默认选择 auth-only change，点击“检查潜在遗漏”。
预期建议检查 tests/test_auth.py：此前与 src/auth.py 共同修改 4 次，比例 100%。
展开历史依据可查看真实合成提交和 diff，并下载遗漏检查报告。
改选 complete auth and test 或 unrelated cache-only，对照结果应没有候选。
这类建议基于目标提交祖先中的历史规律，需人工判断，不证明本次修改一定遗漏或已经完整。

四、再分析真实仓库
选择 GitHub 链接，输入公开仓库首页地址，第一次可选择较小的下载历史深度。
Git 下载需要能连接 GitHub。Windows 已启用的手动系统代理会自动用于下载。
工具会在本机自动创建 data/ 目录保存下载和分析缓存。

五、AI 摘要是可选功能
在左侧 AI 模型设置中填写自己可用的 API Base URL、模型名称和 API Key。
也可以复制 .env.example 为 .env 并填写，然后重启应用。
不要将密钥、.env、.venv 或个人 data/ 缓存放进转发包。
未配置模型时，图表、diff、统计报告及导出仍可使用。

六、当前已知限制
这是一份 MVP 试用版，适合演示和收集反馈。
AI 最多抽取 40 条提交的部分代码差异，可能遗漏后续删除或撤销；摘要需人工核查。
自动引用校验已实现，但不保证 AI 文字结论正确；系统性语义质量验收仍需补齐。
作者按邮箱区分，作者标识数量不一定等于实际人数。
方法识别受语言支持限制；同一方法可列出变更前后位置，不做重命名或跨文件移动追踪。
文件按路径统计；重命名前后的路径尚未合并。
浅克隆和提交上限限制分析覆盖范围，不能当作仓库完整历史报告。
